# FL-01 Workflow Audit

## 1. Workflow Audit Table

Here are 12 recurring tasks from my real week (ML internship, study, and side projects), classified according to Ethan Mollick’s framework.

| Task | Classification | Rationale |
| :--- | :--- | :--- |
| **Writing first-pass Python scripts for data cleaning** | Delegate with review | AI handles boilerplate pandas syntax quickly, but I must review for logical errors and data drops. |
| **Deciding on the core ML lane/research question** | Just me | This requires strategic judgment, business context, and personal interest that AI lacks. |
| **Debugging complex Git merge conflicts** | Collaborate with AI | AI explains the conflict; I decide how to resolve the overlapping logic safely. |
| **Drafting weekly internship update emails** | Delegate with review | AI can format my rough bullet points into a professional email, needing a quick final read. |
| **Reviewing peer code for logic flaws** | Just me | I need to build my own code-reading muscles and understand the architecture deeply. |
| **Formatting Markdown tables for documentation** | Fully automate | Trivial structural work where AI makes zero mistakes. |
| **Interpreting unexpected drops in model performance** | Collaborate with AI | I bring the context of what changed; AI helps brainstorm edge cases or leakage I might have missed. |
| **Writing standard SQL queries to extract data** | Delegate with review | AI is excellent at writing standard JOINs and GROUP BYs, but I must verify the logic matches the schema. |
| **Setting up new Python virtual environments** | Fully automate | A repetitive configuration task where AI-generated bash scripts save time. |
| **Reading and synthesizing long research papers** | Collaborate with AI | I ask the AI to summarize the methodology, but I read the critical sections myself to verify the nuances. |
| **Brainstorming new side-project feature ideas** | Collaborate with AI | AI provides a wide array of creative angles; I select and refine the ones that actually make sense. |
| **Writing final conclusions for a capstone project** | Just me | The conclusion must reflect my own voice, learning journey, and authentic understanding of the work. |

## 2. Target Tasks & Success Definitions

These are the three target tasks I will reuse in FL-02 through FL-04.

### Target Task 1: Structuring and drafting an EDA (Exploratory Data Analysis) notebook
- **Success Definition**: The AI-generated notebook runs without errors, contains clear markdown explanations between code blocks, and correctly visualizes the top 3 correlations within 30 minutes of generation, requiring less than 10 lines of manual code fixing.

### Target Task 2: Summarizing long technical documentation or research papers
- **Success Definition**: The AI summary accurately extracts the core methodology and limitations in under 5 bullet points without missing key context, allowing me to understand the paper's relevance in under 3 minutes.

### Target Task 3: Generating boilerplate unit tests for Python utility functions
- **Success Definition**: The AI generates tests covering at least 80% of edge cases (nulls, zero-values, type mismatches) that pass on the first run, saving me at least 15 minutes of manual typing per function.
